# 三组开发与维护约定

三个组围绕同一个 Graph 和数据契约协作，不再维护两套并行业务流程。基础实现已接通，后续开发重点是质量提升和针对真实项目的评估。

课程开发优先级及六项汇报内容见 [课程项目说明](COURSE_PROJECT.md)。动态规划、跨文件 ReAct、争议复核和失败诊断已接通；后续重点是独立验收与公平对照实验，不能把离线流程通过当成真实模型效果。

## A 组：流程与基础设施

负责 `src/workflow/`、`src/task_intent.py`、`src/source_input.py`、`src/project_tools.py`、`src/model_agent.py`、`src/react.py`、`src/schemas.py`、`src/diff.py`、`src/privacy.py`、`src/serialization.py`、CLI、模型配置和 CI。

已交付：基础节点编排、可选 file_writer 节点、异常边界、有限重试、严格 JSON/schema、差异解析、内存验证基础、凭据脱敏、Markdown/JSON 和候选文件导出。

验收重点：并行结果正确汇合；配置按需读取；导入和离线运行不需要模型；错误不会变成成功；导出不包含原始输入源码；正常模式动态规划并使用 ReAct，可在授权项目内发现上下文并固定快照，调用有上限且可追踪、可恢复。

自然语言入口必须先判断完整请求是否可执行，不能把越界或模糊请求自动替换成 review/fix；拒绝、需澄清、参数冲突和解析异常均不得启动下游任务。语义识别质量需用真实模型另行评估，离线模型只验证路由、契约、权限和恢复行为。

指定文件入口 `--target` 必须绑定真实输入路径和完整快照，不能继续使用另一文件的 diff 作为审查范围；普通 diff 与整文件模式的模型提示和报告范围要区分。写入仍由已有验证链和版本冲突保护控制，目标源码不能被报告导出覆盖。

纯自然语言入口不依赖 target 参数。目标引用必须逐字来自任务，完整路径不能截短后匹配另一个文件；仅有文件名时受限查找并要求唯一。支持多个文件和明确目录，目标提取、文件验证与快照读取属于现有 `task_interpreter` 节点，不额外增加 Agent。恢复必须复用已提交的目标和快照；缺失检查点不能重新挑文件。写入直接作用于原文件路径，同时保留备份与回执。

## B 组：审查与仲裁

负责 `src/review/` 的审查、仲裁、单轮定向补证和专家职责注册 `src/workflow/registry.py`。

已交付：逻辑、安全、质量、测试覆盖、架构、性能、依赖、兼容性八类专家；文件、位置和证据校验；稳定 ID；模型仲裁、同文件重复归并和严重性合并。

后续重点：真实项目误报/漏报评估、证据粒度、跨专家冲突策略、语言专属提示词。不能把“没有提供上下文”推断为“实现一定不存在”；依赖风险只能基于输入证据，不能虚构联网查询结果。

对 C 组输出：`Finding` 列表，其中只有 `confirmed && fixable` 的问题允许生成候选修正。

## C 组：修正与验证

负责 `src/repair/`，包括失败分类诊断、按需补证和受限修复重试。

已交付：修正计划、代码补丁、测试补丁、内存静态检查、模型回归审查及失败反馈。

后续重点：补丁最小性、用例有效性、上下文不足时的处理、语言适配。不得把模型判断或语法编译标为运行测试通过。自然语言要求修正本地文件时，由 `file_writer` 在静态和模型回归通过后调用 `src/file_tools.py` 的 write_file；只审查或只生成补丁时不写入。维护原文件备份、版本冲突拒绝和恢复幂等性，审查专家仍只读。

## 共享契约

`src/contracts.py` 为三组共同维护。修改字段、状态语义或 schema 时，要同步更新生产节点、报告、测试和文档。

- 节点返回变化字段，不返回整个共享状态。
- 并行专家仅能写自己的报告，以及累加的待处理/错误字段。
- 自定义 handlers 属于可信扩展；默认业务会校验模型输出，但 Graph 不为任意外部自定义函数的真实性背书。
- 用 `model=` 注入模拟模型测试实际生产解析与业务逻辑；不要把固定成功报告当作模型质量测试。
- 业务测试显式传 `scaffold=True` 时才使用占位节点。

## 联调与检查

```bash
python -m unittest discover -s tests -v
python -m examples.repair_demo
code-review --scaffold --file examples/review_target.diff
code-review --graph --output output/workflow.mmd
```

另行配置模型后运行 `python -m evals.run_eval`，它会发起真实模型请求，基于结构化发现和人工基准评分。人工语义核对、修正验收与程序自动匹配分别标记；模型回归通过不算运行测试通过。恢复、产物归属和评分命令见 `docs/RUNS_AND_EVALUATION.md`。

A 组同时维护 `src/runtime/` 的运行归属、事件、诊断与 SQLite 恢复；B 组维护人工缺陷基准与 `category` 分类；C 组维护补丁验证阶段诊断及人工修正验收要求。修改数据契约或 Schema 时需验证旧检查点兼容性，代码变更后的恢复必须显式确认。

CI 仅保留无需模型凭据的离线测试、示例和流程图检查。自动调用模型并评论 PR 的工作流已移除，真实模型实验由本地显式执行；写入测试只使用隔离的临时项目，不修改仓库源码。

依赖唯一来源为 `pyproject.toml`；`requirements.txt` 通过 `-e .` 引用它。项目要求 Python 3.11+，不要在代码、示例、测试或 CI 中硬编码真实凭据。
